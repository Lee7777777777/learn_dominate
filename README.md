# 知路 · 学习地图

一个用 Python 编写的本地学习辅助桌面应用。用知识点、论文、课程和实践模块构建学习网络，记录进度、笔记与参考资料。

## 下载 Windows APP（无需 Python）

在 [GitHub Releases](https://github.com/Lee7777777777/learn_dominate/releases/latest) 下载 `ZhiLu-版本号-Windows-x64.exe`，双击即可运行。也提供含说明文档的 ZIP 和 SHA256 校验文件。适用于 Windows 10/11 x64，目前为免安装版，未配置付费代码签名证书。

打包版数据保存在 `%LOCALAPPDATA%\ZhiLu\data`。**更新时关闭 APP，下载并运行新版本 EXE，地图和笔记会继续保留。** 应用右上角「版本与更新」可查看版本、数据位置，并打开最新版本下载页；目前采用手动下载更新，不会在后台替换程序。

旧源码版的 `data` 不会删除。第一次运行 EXE 时，如果 EXE 同目录或上一级目录存在旧版 `data/learning_map.db`，会把整个地图库复制到尚不存在的用户数据目录。本项目的 `dist/版本号/` 本地构建也能识别项目原有数据。已有用户数据目录时绝不覆盖；其他位置可先在源码版导出地图，再在打包版新建地图并导入。

## 启动

需要 Python 3.10 或更新版本，并包含 Tkinter（Windows 官方 Python 安装器中的 Tcl/Tk 组件）。无需 pip 安装第三方库。

在 Windows **双击 `start.vbs`**，直接打开图形界面，不显示 PowerShell 或命令行窗口。也可双击 `start.pyw`（需要正确的 Python 文件关联）。原 `start.bat` 已改为转交无控制台入口，但双击批处理本身可能短暂闪过命令行，因此推荐使用 `start.vbs`。

开发调试时仍可在项目目录运行：

```powershell
python app.py
```

原有数据保留在项目的 `data/learning_map.db`，自动显示为「我的第一张地图」，与启动时的工作目录无关。地图目录保存在 `data/learning_map.library.db`，新地图分别保存在 `data/learning_map_maps/`，不会清空旧地图。启动时恢复上次打开的地图。可指定其他地图库的初始数据库：

```powershell
python app.py --db D:\MyLearning\map.db
```

## 使用方法

顶部「＋ 新建地图」通过设置卡片填写名称、选择背景，创建空白地图。通过「学习空间」下拉框切换地图，通过「地图设置」重命名和更换背景。「外观设置」为每种内容类型挑颜色，并通过滑杆调整模块边框的粗细，两项都跟随地图保存。切换前会提示保存未完成的笔记；同名地图会被阻止。

顶部「画布背景」可切换晴空点阵、暖纸网格和午夜星空，每张地图独立记忆。背景随画布平移缩放。模块采用圆角卡片：边框和类型文字使用该内容类型的颜色，左下角小圆点表示学习状态；选中时在卡片外圈加一道蓝色描边，不会盖住类型颜色。边框粗细在「外观设置」中调整，设置的是 100% 显示下的粗细，缩放时等比变化。午夜星空下内容颜色会自动提亮以保持可读。空白画布可直接点击「添加第一个模块」。

1. 点击「载入示例地图」体验，或点击「＋ 添加内容」打开完整编辑器，填写名称、类型、目标、标签以及笔记、资料，右侧实时预览地图卡片。示例仅能载入空地图。
2. 选择模块，在右侧快速修改并点击「保存」；点击「完整编辑 ↗」或双击地图节点，可以在大编辑器里补充内容。在画布上**右键单击模块**可以直接打开编辑器、补充前置、继续延伸，或删除这个模块（删除前会确认，也可撤销）。编辑器支持 Ctrl+Enter / Ctrl+S 保存。缺少名称、重复关系等错误会在当前编辑器提示，保留已经输入的内容。
3. 点击「＋ 补充前置」或「＋ 继续延伸」打开带关系预览的编辑器，可以创建新内容，也可以复用地图中已有的内容。勾选「保存后继续添加」可连续录入，并始终围绕最初选择的内容建立连接。同名内容需显式勾选允许同名；已有模块通过 ID 区分。
4. 前置依赖 A → B 表示 A 是 B 的前提；进阶延伸 A → B 表示学完 A 后可以继续探索 B；相关内容不区分方向。程序拒绝自连接、重复关系和循环前置依赖。
5. 拖动节点移动。与其他模块的中心、左右边缘或上下边缘接近时会自动吸附，并显示粉色对齐辅助线，方便把模块排成一行或一列；拖动空白区域或按住右键拖动平移，滚轮缩放。「自动排列」按前置依赖分层；延伸和相关关系不决定学习顺序。
6. 左侧按名称、标签、简介搜索，并按类型、状态筛选。「聚焦当前模块」显示当前模块和直接相邻模块，并与筛选条件叠加。
7. 右侧「模块关系」标签页可查看、删除关系，双击关系跳转到相连模块。
8. 「连接已有内容」通过自然语言解释关系方向。「地图操作」菜单集中提供导入、导出和撤销。编辑器中的未保存内容在取消时会先就地提醒，再次取消才放弃。

## 保存与备份

- 创建模块、连接、删除、布局和拖动位置立即写入 SQLite。详情和笔记需点击保存；切换模块、关闭窗口及导入导出时，会提示未保存的修改。
- 「导出备份」导出**当前地图**的 JSON，包含笔记、关系和坐标，不受当前筛选影响；不包含地图名称、背景和外观设置，兼容第一版 JSON 文件。
- 「导入地图」校验完整文件后替换当前地图，不是合并，其他地图不受影响。替换前会保存自动备份至初始数据库目录的 `backups/<地图ID>/` 文件夹。校验失败不会改变当前数据。若要作为新地图导入，先新建空白地图再导入。
- 「撤销删除 / 导入」恢复最近一次删除或导入前的**当前地图完整快照**，因此之后的新增和修改也会回退。恢复前再次备份当前地图。最多保留当前地图本次打开的 10 个撤销点，切换地图或关闭后撤销历史不保留。
- 资料区域保存纯文本链接和文件路径，不复制 PDF 等附件。更换电脑时需自行迁移附件。
- 可关闭 APP 后复制整个 `data` 文件夹备份全部地图、背景与外观设置；JSON 导出适合单张地图迁移。不要单独移动地图目录数据库。
- 无控制台入口的错误日志位于 `data/app.log`，启动失败时会弹窗提示。

## 当前范围

这是可运行的桌面 APP，支持多张独立地图；不同地图之间的模块和笔记互不关联。模块类型可区分，但共用一套字段。暂不包含多地图共享模块、云同步、AI、自动复习或富文本编辑。地图适合个人中小规模知识网络；大量节点时建议筛选和聚焦查看。

## 版本发布流程

版本号统一保存在 `version.py`，更新记录写入 `CHANGELOG.md`。每次完成一批修改后发布一个新版本，例如 `1.0.0 → 1.0.1`（修复）或 `1.1.0`（新增功能）。不是每次保存源码就发布。

代码修改提交到 `main` 后，在项目目录执行：

```powershell
python scripts/release.py 1.0.1 --notes "本次更新的功能说明"
```

脚本会检查工作目录、版本号、远程分支和测试，提交版本号与更新日志，并原子推送 `main` 和 `v1.0.1` 标签。GitHub Actions 在收到 `v*` 标签后测试、打包、运行 EXE 验证，并创建对应 Release 和下载文件。手动运行 workflow 仅测试打包，不从未打标签的分支发布正式版。

如推送失败，版本提交与标签会留在本地；解决网络或权限问题后运行 `git push --atomic origin main v1.0.1`，不要重复创建同名版本。构建失败可在 Actions 中查看日志并重试；已经发布的版本应通过新版本修复，保留历史下载。

本地构建（Windows x64）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe scripts/build_windows.py
```

产物位于 `dist/版本号/`，不提交到源码仓库；GitHub Release 附件保存构建产物。用户数据库不会被打包。实现依据：[PyInstaller 打包选项](https://pyinstaller.org/en/stable/usage.html)、[GitHub Actions 工作流](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)。

## 验证

```powershell
python -m unittest test_storage test_library test_runtime test_ui test_launcher -v
```

UI 测试会短暂打开真实 Tk 窗口，需要可用的桌面环境。所有测试都使用临时数据库，不改动学习数据。

文件结构：`app.py` 为界面，`storage.py` 为 SQLite 与图规则，`library.py` 管理多地图，`start.vbs` / `start.pyw` 为无控制台启动入口，`test_*.py` 为测试。
